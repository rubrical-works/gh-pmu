# Design Decision: Vendored-Schema Validation — Capture, Don't Request

**Date:** 2026-07-14
**Issue:** #886
**Status:** Accepted

## Context

Live-API tests are permanently barred from CI (#876). Their one irreplaceable
value was catching upstream schema changes: hand-written mocks — including the
scenario fixtures from #884 — encode *our assumptions* about GitHub's responses,
so they keep passing when the real schema moves out from under a query. The VCR
decision (#884, same day) explicitly deferred schema-drift detection to this
issue.

The approach — vendor the full public schema, validate with `gqlparser` — was
settled in #884. What was not settled, and dominated the cost estimate, is how to
*obtain* the documents to validate. Most queries are shurcooL struct-based: the
document is generated by the library at call time rather than written literally,
and `constructQuery`/`constructMutation` are unexported
(`cli/shurcooL-graphql@v0.0.4`, `query.go:13,23`). There is no supported way to
ask the library what it would send.

## Decision

**Capture the document, don't request it.** Point the client at a recording
`http.RoundTripper` and read what it sent. Construction and POST both complete
before the response is unmarshalled, so a stub reply is enough to harvest a
document — the call errors afterwards, and that error is discarded.

Three supporting choices:

1. **No fixtures, except where a chain demands one.** 36 of 40 named operations
   are harvested from a bare `{"data":{}}`. The four label mutations resolve the
   label's node id first and bail with `label %q not found` on an empty result,
   so `GetLabelID` gets a canned id. That is the only fixture in the file.
2. **Enumerate coverage from the production sources, not a hardcoded list.**
   `TestNamedOperations_CoverageIsComplete` greps `internal/api/*.go` for
   `gql.Query("…")`/`gql.Mutate("…")` and fails when an operation has no
   invocation. A hardcoded list cannot detect an operation that was never added
   to it. Test files are excluded deliberately: `client_test.go` defines `Test`
   and `Viewer`, which GitHub's schema knows nothing about.
3. **Quarantine known-broken queries by assertion, not exemption.**
   `TestNamedOperations_KnownInvalidStillFail` requires every quarantined entry
   to *still* fail. Fixing the underlying bug turns the suite red until the entry
   is removed.

## Alternatives Considered

1. **Fork or vendor shurcooL to export `constructQuery`** — rejected. A fork to
   read one string, plus a permanent merge burden, during a v1.4.x cycle focused
   on stability.
2. **Reimplement the construction logic** — rejected. It would have to track
   shurcooL's behaviour exactly; when the two drift, the validator silently
   checks a document nobody sends. Worse than no validator, because it reports
   safety it isn't providing.
3. **Validate a representative sample instead of every operation** — rejected.
   The drift this catches is unpredictable by nature; a sample only protects the
   queries someone already thought about.
4. **Hardcode the expected operation list** — rejected, see decision 3 above.
5. **`t.Skip` quarantined operations** — rejected. A skip is invisible in a green
   run and rots into fake coverage. An asserted quarantine cannot.
6. **Vendor a trimmed schema subset** — rejected in #884; the trim step needs its
   own maintenance and can drift silently.

## Consequences

**Accepted:**

- Zero API traffic. The capture transport answers every request; asserted by
  `TestSchemaValidation_NoLiveAPITraffic` rather than claimed.
- The repo grows ~1.5 MB. `.gitattributes` marks the schema `-text`, because
  `core.autocrlf` rewrites LF to CRLF on checkout and would break the provenance
  digest for everyone but the person who vendored it.
- The invocation table is manual: 40 named entries plus 8 raw builders. Adding an
  operation means adding an entry — enforced, not remembered.
- **This catches drift in what we *ask for*, not in what GitHub *returns*.** A
  response-shape change the schema still permits stays invisible. That residual
  gap is the same one #884 accepted; `test/e2e` before releases is the backstop.
- Arguments in the table are throwaway values chosen to clear guards. They are
  not fixtures and assert nothing — if a method grows a new guard, its entry
  fails loudly with "sent no document" rather than silently covering nothing.

## Issues Encountered

**It found a live bug on its first run** — the value proposition, demonstrated
immediately. `GetProjectItemFieldValue` selects `name` directly on
`ProjectV2FieldConfiguration`, which is a **union**; GitHub rejects the document.
Filed as **#888** and quarantined rather than fixed, since production query
shapes are out of scope here.

Two details worth keeping:

- **The bug survived because one call site swallows the error.**
  `cmd/branch.go:975` does `status, _ := ...`, so parking-lot detection silently
  misclassified every issue instead of failing. `cmd/branch.go:695` checks it and
  would hard-fail.
- **Interface-level mocks structurally cannot catch this class of bug.**
  `cmd/branch_test.go` covers these paths across ~85 tests, but it mocks at the
  client-interface level — it asserts what the code *intends* to send. Only a
  check against the real schema sees that the emitted document is invalid. This
  is the same distinction that justifies the branch half of #887.

**The spike's "no fixtures needed" finding was true but incomplete.** It held for
single-call methods (validated against `GetIssue`), but methods that chain a
second call off the first result never reach their second document on an empty
reply. Measured rather than assumed: exactly 4 of 40 needed help, all the same
one.
